# 筹码分布（CYQ）为什么可以估算：原理、模型与局限

> 日期：2026-08-09
> 背景：实现 A 股"套牢盘筛选"时，对东财筹码算法做了 1:1 移植与对账（见 `playground/chip_screen/chip_screen.py`）。本文解释这类模型的估算原理。

---

## 一、筹码分布是什么，为什么拿不到真实数据

**筹码分布**回答的问题是：一只股票的全部流通筹码中，持有者的**成本价**落在各个价格区间的比例各是多少。由它可以推出：

- **获利比例**：成本 ≤ 现价的筹码占比（1 − 获利比例 = 套牢盘比例）
- **平均成本**：筹码分布的中位价格
- **成本集中度**：70% / 90% 筹码所在的价格区间宽度

问题在于：**真实的账户级持仓成本只有交易所和券商知道，且不公开**。普通渠道只有行情数据（OHLC、成交量、换手率）。所以东财、同花顺、通达信等厂商的"筹码分布图"全部是**模型估算值**，不是真实账户统计。

关键在于：虽然是估算，但误差可以被控制在一个可用范围内，原因是下面这个递推结构。

## 二、核心模型：换手率驱动的筹码置换递推

### 2.1 基本假设

每一天的成交，本质是**一部分旧筹码被卖出、同时有一批新筹码以今天的价格区间买入**。模型做两个假设：

1. **均匀卖出假设**：今天成交的筹码，按比例来自当前所有存留筹码（即每个成本档位的筹码都以相同概率被卖出）。于是所有旧筹码整体按 `(1 − 换手率)` 衰减。
2. **今日成本分布假设**：今天新换手的筹码，其成本均匀/三角分布于今天的价格区间 `[最低价, 最高价]` 内。

### 2.2 递推公式

设 `C_t(p)` 为第 t 日收盘后、成本为 p 的筹码占比，`τ_t` 为当日换手率（0~1），`T_t(p)` 为当日新筹码的成本分布（见 2.3），则：

```
C_t(p) = (1 − τ_t) · C_{t−1}(p)  +  τ_t · T_t(p)
          ─────────────────────      ─────────────
          旧筹码：按比例衰减            新筹码：按今日价格分布填入
```

每一天都是"全体旧筹码打 (1−τ) 折 + 加入 τ 份新筹码"。筹码总量恒为 1（归一化）。

### 2.3 当日新筹码的成本分布 T_t(p)

东财的实现（`CYQCalculator`）采用**三角分布**：

- 典型价 `avg = (开 + 收 + 高 + 低) / 4`，认为成交在 avg 附近最密集；
- 在 `[low, avg]` 上从 0 线性升到峰值，在 `[avg, high]` 上线性降到 0，峰值为 `2 / (high − low)`（保证面积为 1）；
- **一字板特例**（high == low）：全部筹码堆在单一价格档位上，高度取 `factor − 1`。

价格轴被离散成 150 档（`factor = 150`），档位间距 `accuracy = max(0.01, (区间最高 − 区间最低) / 149)`。

### 2.4 为什么估算能成立：初始条件被指数遗忘

递推 `C_t = (1−τ_t)·C_{t−1} + τ_t·T_t` 是一个**收缩映射**。假设从某一天起已知行情，但初始分布 `C_0` 完全未知（随便拍一个），经过 N 天后，`C_0` 对当前分布的残留影响是：

```
∏(1 − τ_i)   （i = 1..N）
```

只要区间内有正常换手，这个连乘会指数级趋近于 0。举例：日均换手率 2%，120 个交易日后初始分布残留 `(0.98)^120 ≈ 8.9%`；210 天后 `≈ 1.4%`。

**这就是为什么用最近约 210 个交易日的日 K 就能"算出"筹码分布**：不需要知道历史上谁在什么价位买的——时间久了，老筹码要么已卖出（被模型衰减掉），要么占比小到可以忽略。模型误差主要来自假设本身（见第四节），而不是初始条件。

换句话说，换手率提供了"筹码替换速率"的观测量，价格区间提供了"新筹码成本"的观测量，两者递推叠加，就把不可观测的成本分布变成了可估计量。

## 三、从分布到指标

估算出 `C(p)` 后（离散为 150 档 `xdata[i]`，对应价格 `minprice + i·accuracy`）：

- **获利比例** `= Σ xdata[i]（所有满足 价格_i ≤ 现价 的档）/ Σ xdata`
- **平均成本** = 累计筹码首次超过 50% 的价格档（即分布中位数）
- **90% / 70% 成本区间** = 累计筹码 5%→95%（或 15%→85%）对应的价格区间，**集中度** = `(高 − 低) / (高 + 低)`

## 四、假设的局限与误差来源

模型能用，但要知道它哪里会错：

| 局限 | 影响 |
|------|------|
| **均匀卖出假设不真实**：实际是获利盘/解套盘更倾向卖出，死筹长期不动 | 高位套牢盘被低估衰减，极端套牢股的"获利比例"可能略偏大 |
| **换手率口径**：模型用流通股本换手率，但大股东/锁仓筹码实际不换手 | 大股东占比高的股票，估算的有效换手偏慢，分布偏"旧" |
| **大宗交易、协议转让**：价格可能偏离当日区间 | 这部分筹码成本被错误地按当日三角分布处理 |
| **分红送配除权**：必须用不复权或做复权一致处理，否则成本轴错位 | 数据预处理错误会直接算错（本项目统一用不复权） |
| **参数差异**：档位数、三角分布形状、典型价定义各家不同 | 东财/同花顺/通达信的筹码图互有小差异，属正常 |
| **窗口长度**：换手极低的股票，210 天窗口外仍有可观残留筹码 | 僵尸股的分布低估远端成本 |

实践中它适合回答**结构性问题**（套牢盘重不重、筹码集中在哪、获利盘比例量级），不适合当精确账户数据用。

## 五、本项目的实现与对账

实现：`playground/chip_screen/chip_screen.py` 中的 `cyq_last()`，为东财 `CYQCalculator`（akshare `stock_cyq_em` 内嵌 JS）的 Python 移植，参数一致：150 档、三角分布、`(o+c+h+l)/4` 典型价、一字板特例、210 日窗口。

数据输入只需要日 K 的 OHLC + 换手率，本项目用腾讯源（`akshare.stock_zh_a_hist_tx`，自带 turnover）。

对账（2026-08-07，平安银行 sz000001，不复权，210 日）：

| 指标 | 本地 CYQ（腾讯数据） | 东财官方 |
|------|---------------------|----------|
| 获利比例 | 0.5834 | 0.5835 |
| 平均成本 | 11.09 | 11.09 |

差异在小数点后第四位，来自离散化舍入（JS `toPrecision(12)` 与 Python 浮点的细微差别），可忽略。
