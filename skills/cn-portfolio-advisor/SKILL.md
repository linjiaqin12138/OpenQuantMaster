# CN Portfolio Advisor

每次调用完成一次“交易日检查 → 读取状态 → 获取行情与增量新闻 → 更新观察事件 → 形成建议 → 通知并保存状态”的周期。只提供建议和通知，不自动下单。

调度由 agentmanage 负责；本 Skill 不创建或管理调度任务。默认使用 Asia/Shanghai 时区的 09:20（盘前）、11:35（午间）和 14:45（尾盘）三个时点。黑天鹅和重大风险只在任务运行时发现并立即通知，不代表三次运行之间存在持续监控。

配置模板见 [prompt-template.md](prompt-template.md)。

## 硬性要求

- 行情、新闻和通知必须通过 `qm-cli`；不要直接调用数据商 SDK、HTTP API 或编写脚本绕过它。假设 `qm-cli` 已在 PATH 中，直接运行，不传 `--config`。
- 不要阅读、搜索或翻查 qm-cli / OpenQuantMaster 源码来了解用法。只能使用本 Skill 列出的命令，以及下列帮助命令；未列出的服务或子命令不要执行。
- 本地状态文件使用文件工具读写。不得把凭据、通知 Token、环境变量内容或配置秘密写入状态、日志、通知和回复。
- 持仓是用户提供的静态快照，不从行情、新闻或建议推断实际成交。只有用户明确告知变动，或用户提供更高 `portfolio_revision` 的持仓配置时，才能修改持仓。
- 本 Skill 不执行交易。建议必须标明依据、风险和失效条件，不承诺收益，不把传闻、政策预期或“利空出尽”当成确定事实。
- 当天不是交易日时，在调用任何行情、新闻或通知服务之前结束；不生成建议，不发送常规通知，不推进新闻游标。
- 每个有效运行周期都发送一次简明组合建议；重大风险或黑天鹅另行立即通知。相同事件没有实质进展时不要重复告警。

## 配置

从用户最新指令和 agentmanage 提供的 prompt 中读取配置。可复制 `prompt-template.md` 修改。

| 配置 | 默认值 | 说明 |
|---|---|---|
| `session` | `auto` | `auto` 按运行时间识别 `pre_open` / `midday` / `pre_close`；也可显式指定 |
| `timezone` | `Asia/Shanghai` | 交易日和运行时点所用时区 |
| `state_file` | `.agent-state/cn-portfolio-advisor/state.json` | 持仓、新闻游标和观察事件的持久化文件 |
| `portfolio_revision` | 无 | 持仓版本；用户每次修改持仓时递增，防止旧模板覆盖新持仓 |
| `portfolio_confirmed` | `false` | 只有用户确认持仓快照后才能设为 `true`；明确空仓也可为 `true` |
| `holdings` | `[]` | 持仓列表，见下文；首次使用前必须填写或由用户明确确认空仓 |
| `cash_cny` | `null` | 可选可投资现金；未知时不得假设可用资金 |
| `risk_profile` | `balanced` | `conservative` / `balanced` / `aggressive`，只影响建议，不代表实盘授权 |
| `max_single_position_pct` | `20` | 建议中的单一标的组合市值占比上限 |
| `benchmark_symbol` | `000300.SH` | 组合参考基准；无法使用时由用户更换 |
| `bar_limit` | `120` | 每个标的的日线数量 |
| `news_sources` | `cls,em,sina,ths,futu` | 宏观和事件快讯来源 |
| `news_limit` | `100` | 宏观或事件快讯过滤后的上限 |
| `stock_news_limit` | `50` | 每个持仓公司的候选新闻上限 |
| `initial_news_lookback_hours` | `24` | 首次运行或某新闻流无有效游标时的回看窗口 |
| `news_overlap_minutes` | `15` | 增量筛选的重叠回看时间，用于降低边界遗漏 |
| `non_trading_dates` | `[]` | 当年法定节假日、休市日等，ISO 日期列表 |
| `trading_dates_override` | `[]` | 强制视为交易日的日期；仅用户确认无误时使用 |
| `calendar_confirmed_through` | `null` | 本地休市日历已核对覆盖到的日期；超出该日期不运行分析 |
| `watch_events` | `[]` | 用户固定关注的初始事件；运行中发现的重大事项写入状态文件 |
| `instructions` | 无 | 用户偏好、禁止事项和特殊指令；最新明确指令优先 |

持仓字段至少包含：

- `symbol`：行情代码，如 `600519.SH`；`market` 默认 `a_share`。
- `name`：便于识别和匹配新闻的名称。
- `news_symbol`：`stock-recent` 使用的六位股票代码或关键词；仅股票持仓使用。
- `news_keywords`：可选的行业、公司、基金名称或跟踪指数关键词。基金必须提供有意义的词组，用于 `recent` 快讯查询；股票也可用它补充行业事件。
- `quantity`、`cost_price`：实际数量和单位成本；未知字段设为 `null`，不得猜测。
- 可选 `max_position_pct`、`notes`：覆盖组合默认限制或记录用户特殊约束。

## qm-cli 约定

所有数据与通知命令使用 `-o json`。示例使用默认值，实际执行时须替换为配置的代码、市场、数量上限、来源和关键词，不把示例持仓当成真实查询对象。命令失败时保留非零状态和 stderr 安全摘要，不把失败当成空数据。只允许用以下帮助命令确认参数：

```bash
qm-cli help
qm-cli list
qm-cli run ohlcv --help
qm-cli run news-fetcher --help
qm-cli run notification --help
```

## 本地状态文件

每个周期先读取 `state_file`。至少维护：

```json
{
  "version": 1,
  "portfolio_revision": 0,
  "portfolio_confirmed": false,
  "holdings": [],
  "cash_cny": null,
  "preferences": {},
  "watch_events": [],
  "news_state": {
    "streams": {},
    "seen": []
  },
  "recent_alerts": [],
  "last_advice": null,
  "last_successful_run_at": null,
  "updated_at": null
}
```

状态规则：

1. 首次初始化时，只有 `portfolio_confirmed: true` 且持仓为用户真实快照，或用户明确确认当前空仓，才能写入持仓。示例或空白占位不能当作真实持仓。
2. prompt 中 `portfolio_revision` 高于状态时，按用户新快照整体替换持仓并更新版本；等于状态时沿用状态；低于状态时保留状态中的新持仓，并在结果中提示模板版本过旧。
3. 用户在对话中明确告知持仓变化时，更新状态中的持仓和版本。不得因为建议买入/卖出、价格变化或新闻内容而修改实际数量与成本。
4. `preferences` 保存用户风险偏好、限制和特殊指令；与最新明确指令冲突时以最新指令为准。
5. 初始 `watch_events` 只合并状态中不存在的新 id；同一 id 以状态中的进展为准，除非用户明确给出修改。避免旧模板把已结束事件重新加入。
6. `news_state.streams` 按宏观、每个持仓、观察事件分别保存各来源的上次成功运行时间和实际覆盖情况；`seen` 保存有界的新闻 id、URL 或内容哈希及时间，用于去重。定期清理超过 30 天的去重记录，避免文件无限增长。
7. `recent_alerts` 记录重大风险事件及最近一次实质进展，避免重复告警；不能只凭相似标题认定没有进展。
8. 只有该新闻流所需命令成功且结果完成本地筛选后，才推进相应游标。失败、非交易日或周期中途终止不得把未完成区间标为已覆盖。
9. `last_advice` 保存最近一次建议及依据，供无重要增量时检查连续性；它只是历史建议，不代表已成交。
10. 状态损坏、关键字段无法解析或持仓版本冲突时，不猜测恢复；保留原文件，说明需要用户确认。写状态应维持有效 JSON，并避免并发周期同时写同一文件。

## 单个运行周期

### 1. 交易日与配置检查

使用当前日期和本地配置判断，不调用行情猜测当天是否开市：

1. 日期在 `trading_dates_override` 中，视为交易日。
2. 否则周末或日期在 `non_trading_dates` 中，直接结束。
3. 其余工作日只有在 `calendar_confirmed_through >= 当前日期` 时才视为已确认交易日。日历未覆盖时不运行分析，并通知用户更新休市日历；这不是非交易日常规跳过。
4. 检查 `portfolio_confirmed`、持仓版本和必要字段。未确认真实持仓时停止分析并通知用户补充；明确空仓时可以仅跟踪基准、宏观和观察事件，不给持仓操作建议。

### 2. 获取行情

对基准和每个持仓分别运行以下命令，将代码替换为实际配置；不执行未列出的批量或实时行情命令：

```bash
qm-cli run ohlcv --symbol 000300.SH --market a_share --interval 1d --limit 120 -o json
qm-cli run ohlcv --symbol 600519.SH --market a_share --interval 1d --limit 120 -o json
```

检查返回条码、最新时间和异常。盘前最新完整日线通常是上一交易日；午间和尾盘若只有上一交易日数据，必须注明缺少当日行情，不给出依赖精确现价的建议。不得把日线数据声称为实时报价。

### 3. 获取增量新闻

宏观与市场快讯：

```bash
qm-cli run news-fetcher --mode recent --sources cls,em,sina,ths,futu --keywords 央行,货币政策,降息,加息,降准,财政政策,证监会,金融监管,地缘政治,关税,汇率,通胀,PMI,CPI,PPI,GDP,原油,黄金,美债,流动性 --keyword-match any --limit 100 -o json
```

每个股票持仓的公司新闻，逐个运行并替换为实际 `news_symbol`：

```bash
qm-cli run news-fetcher --mode stock-recent --symbol 600519 --limit 50 -o json
```

每个基金持仓用其 `news_keywords` 查询相关行业、指数和基金公司事件；股票有额外行业关键词时也使用同一形式。将示例关键词替换为实际配置，未配置有效关键词时跳过并披露该持仓新闻流缺失：

```bash
qm-cli run news-fetcher --mode recent --sources cls,em,sina,ths,futu --keywords 基金名称,跟踪指数,相关行业,基金公司 --keyword-match any --limit 100 -o json
```

对所有活跃观察事件，将关键词合并后运行一次；关键词过多时分批使用同一命令，并确保每批上限和去重规则一致：

```bash
qm-cli run news-fetcher --mode recent --sources cls,em,sina,ths,futu --keywords 处罚立案,处罚落地,业绩预告,重大合同,资产重组,行业政策,产品涨价,停产,召回,诉讼,减持,解禁 --keyword-match any --limit 100 -o json
```

上面观察事件命令中的关键词只是默认通用词。状态中存在具体事件时，必须将事件关键词加入列表；没有活跃观察事件时跳过该命令。

`recent` 和 `stock-recent` 都只是提供方当前最新页，不支持固定 `since` 窗口。因此必须：

1. 记录本周期开始时间。首次运行或无有效游标的流只回看 `initial_news_lookback_hours`；后续以该流各来源上次成功运行时间为起点，并向前重叠 `news_overlap_minutes`。
2. 按新闻发布时间过滤，再按 id、URL 和内容语义去重。重叠窗口内已处理的旧闻不重复进入报告。
3. 分开记录宏观、持仓和事件流的实际时间覆盖及各来源错误；某来源失败时保留其旧游标，不能由其他来源成功代替。
4. 如果返回结果的最早时间仍晚于应覆盖起点、达到数量上限或存在缺失时间戳，标记“可能存在新闻缺口”，不得声称完整覆盖上次运行至今。
5. 区分已确认事实、市场评论和未证实消息。没有重要新增时写“无重要增量”，不要重复罗列旧闻或鸡毛蒜皮的信息。

### 4. 更新观察事件

每个观察事件至少记录：

```json
{
  "id": "stable-event-id",
  "title": "事件摘要",
  "symbols": ["600519.SH"],
  "keywords": ["公司名", "处罚落地"],
  "trigger": "可验证的落地条件",
  "hypothesis": "可能影响及方向，仅为待验证假设",
  "status": "watching",
  "pinned": false,
  "source_urls": [],
  "created_at": "<ISO-8601>",
  "updated_at": "<ISO-8601>",
  "last_news_at": null,
  "next_review_at": null,
  "expires_at": null
}
```

维护规则：

- 只加入有明确对象、潜在重要影响和后续可观察节点的事件，例如处罚/政策落地、业绩或合同披露、重组进展、行业供需变化、重大诉讼、停产和解禁。
- 普通评论、重复旧闻、无新信息的日常波动和鸡毛蒜皮事项不加入。
- 新事件与现有事件按标的、主题和触发条件去重；有实质进展时更新同一事件，不重复新建。
- `pinned: true` 的用户关注项不得擅自删除或降低优先级。其他事件触发后可标为 `triggered`，确认结束后标为 `resolved`，到期且无后续价值时标为 `expired`。
- “利空出尽”“政策利好”等只能写成假设；触发后仍须结合实际内容、市场预期和行情判断，不直接等同于买入建议。

### 5. 形成建议

先检查组合风险，再看单标的催化。结合持仓数量和成本、最新可用行情、增量新闻、观察事件、用户现金和风险偏好，给出：

- 组合层面的总仓位、集中度、现金和重要风险建议。
- 每个相关持仓的 `买入/加仓/持有/减仓/清仓/观望` 之一，尽量给出目标仓位或数量区间，而非只有方向。
- 主要依据、数据时间、相反风险、触发条件和失效条件；没有新信息时可以维持上次逻辑，但不得伪造新理由。
- 事件驱动建议须区分“事件未落地”“已落地待市场验证”和“已失效”。黑天鹅下先保护本金和流动性，不因恐慌标题机械给出全仓卖出。
- 考虑 A 股 T+1、适用标的的最小交易单位和涨跌幅限制；数据不足时只给保守条件建议，不假设能按某个价格成交。

### 6. 通知并保存状态

常规周期通知命令：

```bash
qm-cli run notification --title "A股持仓建议｜盘前" --content "时间：<ISO时间>\n数据：<行情与新闻实际覆盖时间>\n组合：<总仓位/集中度/现金建议>\n持仓建议：<逐项动作、理由、失效条件>\n增量新闻：<重要新增或无重要增量>\n观察事件：<触发/进展/无重要进展>\n风险：<数据缺口与主要风险>" --format markdown -o json
```

午间和尾盘将标题中的“盘前”替换为“午间”或“尾盘”。通知应短而可执行，不堆砌未过滤新闻。

重大风险或黑天鹅单独立即发送：

```bash
qm-cli run notification --title "重大风险提醒｜<标的或宏观事件>" --content "时间：<ISO时间>\n事件：<已确认事实，传闻须明确标注>\n影响：<受影响持仓和可能传导路径>\n建议：<保守处置、触发条件与失效条件>\n来源：<来源、发布时间、URL>\n不确定性：<待核实事项>" --format markdown -o json
```

黑天鹅包括可能造成市场或持仓重大非线性损失的突发战争、金融系统风险、重大监管处罚、财务造假、核心产品事故、退市或长期停牌风险等。可信重大事件无需等待所有来源一致才提醒，但必须标明核实程度；同一事件没有实质进展时不重复告警。

通知完成后保存状态。通知失败时仍保存已完成的分析和新闻处理状态，在周期结果中直接说明原始建议及通知失败原因，不能假装送达。

## 错误处理

- 行情失败或过期：相关标的不给依赖现价或精确数量的新增建议；已有持仓可基于可靠重大新闻给保守风险建议。
- 新闻命令或部分来源失败：披露缺失并保留对应游标，不声称“无新闻”；其他可靠数据仍可支持保守建议。
- 新闻覆盖存在缺口：在常规通知中明确提示，不能通过扩大数量上限后假装已经补齐。
- 持仓未确认、状态损坏或版本冲突：停止基于该状态的组合建议，通知用户核对，不自行编造持仓。
- 交易日历未覆盖：工作日暂停分析并提醒更新日历；已确认非交易日则安静跳过。
- 通知失败：在周期结果中直接给出应通知内容和失败摘要。
- qm-cli 不可用：停止外部数据和通知操作，直接报告阻塞，不改用其他服务绕过。

## 周期结果

给用户一个简短结果：运行时段、交易日判断、行情与新闻实际覆盖时间、组合及逐项建议、重要增量与事件进展、通知送达状态、状态文件更新结果和任何数据缺口。非交易日只需说明已跳过，不生成交易分析。
